# 运行架构

## 接收与调度

`main.c` 用1ms节拍调度按键、声音、背光、电池、射频及分块屏幕刷新。PB10中断采样接收数据，前台以有界工作量解码。LCD使用期望/已显示缓冲，只发送变化部分。

`radio_task.c` 分步处理启动、CTS、配置和接收状态。`pocsag.c` 处理同步、极性、地址、跨批次消息及BCH纠错；不可纠正码字会丢弃当前消息，防止继续拼接错误地址后的数据。

## 报文与关联

`lbj_parse.c` 提取数字车次、速度、公里标、前缀、机车登记号及原始GBK线路字节。前缀取自报文，不由分类猜测。登记号保留全部五位数字，四位车型匹配与编号首位可能重叠。

`lbj_state.c` 缓存4个车次/方向会话，基础更新保留近期详情。独立详情没有已解析的数字车次，只配给最近同方向8秒内的短报文。同方向8秒内出现不同数字车次时，最后一次切换后的8秒内跳过独立详情；合并报文本身带身份，可直接使用。

新详情按整体快照替换，缺字段不继承旧详情。这不能识别完全漏收的另一趟车，也不能完全区分数字相同而字母不同的车次。`AM`只是因交错保护跳过的详情数。

## 历史、界面与休眠

`history.c` 用2000字节RAM保存100个不同车次；重复更新移到最前，满额淘汰最久未更新项，重开清空。前缀可区分已知身份，无前缀时仍有歧义。目前不存线路、不写外置Flash。

`app_ui.c` 处理页面与父级返回，`app_view.c` 绘制车次、电量、速度/公里标、机车、类别及历史。字库为16×16汉字/8×16 ASCII子集。

`power_sleep.c` 关机关闭SysTick并进入DeepSleep。绿键PB07唤醒后恢复节拍，连续1500ms启动，提前松开重新休眠。临界区覆盖最后检查和WFI，避免漏边沿。实际待机电流需单独测量。

## 升级

`iap/` 提供8KiB引导、固定应用区、暂存区和元数据。完整上传校验后才安装，未提交数据不替换当前应用；安装中断可根据待安装记录恢复。正常接收不轮询串口升级协议。
